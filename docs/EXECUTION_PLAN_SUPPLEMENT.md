**Purpose:** Supplement the current execution plan with new strategic build ideas from recent ecosystem research: cross-protocol neutrality, Agent Economy Index, AgentCrush Labs, evaluator-agent markets, agent commerce readiness, SURF/onchain data ingestion, and A2A/ACP implications for traditional industries.

## 0. Strategic correction: AgentCrush must stay neutral

AgentCrush should not be positioned as belonging to x402, ERC-8004, Coinbase, Kite, Agentverse, Virtuals, Fetch, Bittensor, OpenServ, Daydreams, Giza, or any single ecosystem.

AgentCrush is a platform-level intelligence source.

Correct framing:

**AgentCrush tracks the agent economy across protocols, registries, marketplaces, frameworks, and payment rails.**

AgentCrush should integrate with many systems when useful, but should not identify as a project inside any one of them.

Use language like:

- “tracks across”
- “indexes signals from”
- “cross-protocol”
- “agent economy intelligence”
- “evidence index”
- “market intelligence”
- “machine-readable agent intelligence”
- “protocol-neutral agent intelligence”

Avoid language like:

- “the trust layer”
- “the reputation layer”
- “the identity layer”
- “built on x402”
- “built on ERC-8004”
- “the x402 reputation provider”
- “the ERC-8004 trust provider”

**Clarification:** “trust” can still be used descriptively for product outputs such as trust-summary, trust context, and credibility signals. The restriction is on positioning AgentCrush as the protocol-level trust/reputation/identity layer. Endpoint names (trust-summary), UI labels (Trust Context panel), and evidence descriptions (machine-readable credibility signals) are all fine.

AgentCrush can use x402, read ERC-8004, monitor Virtuals ACP, ingest Agentverse, expose MCP, index Daydreams agents, watch OpenServ startups, and enrich from SURF — but its own identity remains independent.

## 1. Source synthesis: what the new reports add

### 1.1 Khala OpenClaw report

The useful insight is not “buy OpenClaw tokens.” The useful insight is that autonomous agents are being judged by **verifiable output**, not narrative.

Relevant signals:

- deployed apps
- smart contracts deployed
- wallets created
- external revenue
- treasury movements
- fees earned
- products shipped
- third-party forks/adoption
- agent-to-agent coordination primitives
- autonomous pivots
- public receipts

AgentCrush implication:

Add “autonomous output” as a future evidence category. Do not score this yet unless the data is verifiable.

Potential future fields:

- `deployed_apps_count`
- `deployed_contracts_count`
- `external_revenue_reported`
- `revenue_source_type`
- `public_receipt_url`
- `agent_wallet_address`
- `treasury_url`
- `autonomous_pivot_events`
- `third_party_forks`
- `agent_coordination_primitives`

This belongs under scoring hardening / source ingestion, not as a new product.

### 1.2 Khala Bittensor report

The useful idea is that Bittensor subnets are not just projects; they are **competitive intelligence markets**. Subnets can be evaluated by output quality, incentives, revenue, organic vs sponsored usage, customers, and validator/miner health.

AgentCrush implication:

Add Bittensor as a monitored infrastructure category later, not immediately.

Future page type:

`/ecosystem/bittensor`

Possible index:

**Decentralized AI Infrastructure Index**

This is lower priority than agent commerce, but it belongs in Ajsa monitoring because Bittensor subnets may become backend infrastructure for agents.

### 1.3 Khala decentralized robotics report

Robotics is not immediate, but it validates the long-term machine economy thesis. Robots will need identity, payments, mapping, coordination, execution logs, and reputation.

AgentCrush implication:

Create a future category:

**Physical AI / Machine Agents**

Do not build now. Add to Ajsa catalyst watch:

- first commercial robot using x402 or similar payment rail
- OpenMind / peaq / GEODNET / Auki / BitRobot / CodecFLOW updates
- robot-agent marketplaces
- machine identity standards

This matters because AgentCrush should eventually track not only software agents, but also machine agents and robot agents if the market moves there.

### 1.4 Virtuals ACP report

ACP matters because it defines agent commerce around a transaction lifecycle:

1. request
2. negotiation
3. transaction / escrow
4. evaluation
5. completion / settlement

The most important part for AgentCrush is the **evaluation phase**. Evaluator agents can become a market of their own. They verify whether a delivered service met agreed terms.

AgentCrush implication:

AgentCrush should not compete with ACP. It should index ACP services, completed jobs, evaluator agents, and public transaction/evaluation signals where available.

Possible future product:

**Evaluator Agent Index**

This would rank evaluator agents by domain, usage, historical performance, disagreement rate, job volume, and specialization.

This is important because evaluator agents may become a major category of agent infrastructure.

### 1.5 a16z “missing infrastructure for AI agents”

The useful thesis:

AI agents are becoming economic actors, but they lack portable identity, authorization, payments, governance, verification, and user-control infrastructure.

Key AgentCrush implication:

The bottleneck is not intelligence. It is verification, authorization, and auditability.

AgentCrush should position itself as an intelligence layer that helps humans and agents answer:

- Who is this agent?
- Where is it active?
- What has it done?
- What protocols does it support?
- What evidence exists?
- What is verified vs self-reported?
- What changed recently?
- What should be watched?

This supports the AgentCrush neutrality thesis.

### 1.6 SURF report

SURF is useful as a data provider, not as the moat.

It may help with:

- onchain wallet intelligence
- social signals
- token/project intelligence
- fundraising data
- prediction/social trend data
- MCP-based data access
- Ajsa brief enrichment

AgentCrush implication:

Use SURF as one input where useful. Do not make AgentCrush dependent on SURF.

Correct architecture:

SURF / x402 / ERC-8004 / ACP / Agentverse / GitHub / npm / PyPI / HN / Reddit / Bazaar  
→ AgentCrush normalization  
→ historical snapshots  
→ profiles  
→ rankings

→ badges  
→ Agent Economy Index

### 1.7 Giza

Giza is a good example of “agents as interface.” Users specify intent; agents execute across markets. Their emphasis on verifiable decision-making is relevant.

AgentCrush implication:

Add Giza to the index and Ajsa watchlist.

Potential future category:

**Capital Management Agents**

Do not build finance-specific scoring yet. Just track the category.

### 1.8 OpenServ

OpenServ is relevant because it packages autonomous startups with specialized agents: community lead, marketing lead, growth lead, enterprise custom solutions.

AgentCrush implication:

OpenServ-style “autonomous startup” projects should be indexed as a category. More importantly, OpenServ validates the service model: companies will pay for agentic implementation if it is packaged clearly.

This supports AgentCrush Labs.

### 1.9 Daydreams

Daydreams describes itself as tools for building agents for commerce.

AgentCrush implication:

Add Daydreams as:

- indexed framework
- Ajsa source
- possible integration target
- agent-commerce framework category

Do not build around it exclusively.

### 1.10 Agent social / identity platforms

Moltbook was acquired by Meta (March 2026). Public framing was "AI agent social network." Strategic substance appears to be agent identity, registry primitives, owner-tethering, and visibility/attention infrastructure.

This opens a new monitored surface: **agent social / identity platforms**.

Examples:
- Moltbook (now under Meta / Meta Superintelligence Labs)
- Future agent-social networks
- Agent-native Farcaster accounts

Possible evidence signals from this surface:
- agent profile URL
- owner verification / human-tethering
- posting / activity count
- inbound and outbound agent mentions
- agent-to-agent interactions
- community / subnetwork participation
- social graph references

Evidence caveat:
- This surface is noisy, gameable, performative, and lower-confidence than GitHub / packages / onchain / payment evidence.
- Social activity counts as attention evidence, not trust or reputation.
- Should not feed scoring until source quality and reliability are proven.
- Do not conflate agent personas (social posting) with developer agents or economically active agents.

Use as monitoring / input first. Build an adapter only when a reliable, structured data source exists.

## 3. New Section 12: Protocol-neutral positioning system

### Principle

AgentCrush must be legible as neutral infrastructure.

It can connect to many ecosystems, but public copy should always say “across,” not “inside.”

### Public copy standard

Homepage:

**Market intelligence for the agent economy.**

Subheadline:

**Track AI agents across open-source, x402, ERC-8004, A2A, MCP, and agent marketplaces. Compare activity, adoption, history, and machine-readable credibility signals.**

API wording:

**Structured agent intelligence for autonomous workflows.**

Builder wording:

**Get your agent indexed, compared, and discoverable across the emerging agent web.**

Company wording:

**Understand which agent infrastructure is active, credible, and economically relevant.**

### Protocol mention rule

Mention protocols only as tracked sources, not as identity.

Good:

“AgentCrush tracks agents across x402, ERC-8004, A2A, MCP, and marketplaces.”

Bad:

“AgentCrush is the x402 trust layer.”

Bad:

“AgentCrush is the reputation layer for ERC-8004.”

### Integration rule

Any integration must follow adapter architecture:

`external source -> normalized source table -> AgentCrush evidence graph -> public/API surface`

No integration should write directly into core score without normalization and evidence tiering.

1. Can AgentCrush index it?
